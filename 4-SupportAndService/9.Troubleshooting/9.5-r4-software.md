# 9.2 Software issues

## `#error "This library only supports boards with ESP32 processor."`

```
M5Stack.h:178:2: error: #error "This library only supports boards with ESP32 processor."
MyCobotSaver.h:7:10: fatal error: FS.h: No such file or directory
```

`ParameterList.h` is still configured for the M5. Fix it as in
[6.1.2 Simple Use](../../3-FunctionsAndApplications/6.developmentGuide/Arduino/10.2-arduino_use.md).

**If you already edited it and still see this**, you almost certainly edited
`examples/MyCobot280/MyCobot280_Arduino/Mkr/ParameterList.h`. That copy is not
used by the build — only the one in the **library root** is compiled.

The error trace names the file actually being read:

```
In file included from .../libraries/MyCobotBasic/ParameterList.h:28,
                 from .../libraries/MyCobotBasic/MyCobotSaver.h:5,
                 from .../libraries/MyCobotBasic/MyCobotBasic.h:7,
```

## `reference to 'data' is ambiguous`

```
Transponder.ino:131:11: error: reference to 'data' is ambiguous
```

The official `Mkr/Transponder.ino` does not compile for the R4 as shipped. The
sketch has `using namespace std;` and the R4 core declares `std::data`, so the
global `int data` becomes ambiguous. Rename it to `rx_byte` — see
[6.1.2 Simple Use](../../3-FunctionsAndApplications/6.developmentGuide/Arduino/10.2-arduino_use.md).

## `fatal error: stddef: No such file or directory`

```
avr-libstdcpp/new:40:10: fatal error: stddef: No such file or directory
```

You selected `MyCobot_Uno` instead of `MyCobot_Mkr`. That profile pulls in the
AVR `libstdc++` shim, which the R4's ARM toolchain neither needs nor tolerates.

## Upload fails: `Serial port busy` or `No device found`

Something else holds the port — a Python session, a REPL, or the Serial
Monitor. Close it.

If nothing holds it and upload still fails, **retry**. The R4 frequently needs
a moment to settle after a port is released; two failures followed by success
on an identical third attempt is normal and does not indicate a fault.

## Everything returns `-1`

No bytes are arriving at all. This is not a software problem — see
[9.3 Hardware issues](9.3-hardware.md).

## `get_coords()` returns 4 values instead of 6

You are using the `MyPalletizer260` class against a 280. Use `MyCobot280`.

## `AttributeError: no attribute 'get_robot_version'`

Not a method on `MyCobot280` in pymycobot 4.0.6. Use `get_basic_version()` or
`get_system_version()`.

## A move is cut short by the next command

You are detecting completion by comparing successive `get_angles()` samples.
Immediately after `send_angles()` the arm has not started yet, so two equal
reads look like "finished". Use `is_moving()` — a worked example is in
[6.1.6 Build and upload, step by step](../../3-FunctionsAndApplications/6.developmentGuide/Arduino/10.6-arduino_ide_build.md).
