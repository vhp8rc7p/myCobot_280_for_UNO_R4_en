# 9.0 Others

## Can I still use the M5Stack Basic?

Yes. The change is entirely in `ParameterList.h`. Copy the M5 profile back over
the root file and the library builds for the M5 again.

Note it is a **global** switch — the library is configured for one board at a
time. If you alternate between boards, keep both `ParameterList.h` variants and
swap them, or use a self-contained project like
[MyCobot280_R4_Transponder](https://github.com/vhp8rc7p/MyCobot280_R4_Transponder)
that bundles its own copy and never touches the installed library.

## Does the RoboFlow firmware run on an R4?

No. It is built on `M5Stack.h`, `WiFi.h`, `BLEDevice.h` and
`BluetoothSerial.h` — all ESP32-only — plus a screen UI, a FreeRTOS task and a
TOF sensor. Its `Uart` transponder mode is the portable part, and that is what
[6.1.4 Transponder mode](../../3-FunctionsAndApplications/6.developmentGuide/Arduino/10.4-transponder.md)
reimplements.

## R4 WiFi or R4 Minima?

Either works for driving the arm. The WiFi additionally has the 12x8 LED
matrix covered in
[6.1.5 LED matrix](../../3-FunctionsAndApplications/6.developmentGuide/Arduino/10.5-led_matrix.md).

The R4's WiFi radio is **not** used — transponder mode here is USB-only. An M5
build offers WiFi and Bluetooth transponder modes; there is no equivalent here.

## Does myStudio flash the R4?

No. myStudio targets the M5 and Atom boards. Flash the R4 from the Arduino IDE.

The **Atom** at the arm's end effector is unchanged and is still flashed with
myStudio as normal. Only the base controller changes.

## Can ROS, ROS2 or myBlockly use this?

Yes, provided the R4 is running transponder mode. They all speak the same
serial protocol over a COM port and cannot tell the difference between an R4
and an M5.

## Why is the profile called "Mkr" when I have an UNO R4?

It is a serial-port profile, not a board identity. `MyCobot_Mkr` means "use
`Serial1`, and do not include the AVR shim" — both correct for the R4. You do
not need to own a MKR. See
[6.1.2 Simple Use](../../3-FunctionsAndApplications/6.developmentGuide/Arduino/10.2-arduino_use.md).

## Why not `MyCobot_Uno`, given I have an Uno?

Because it maps the arm to `Serial`. That is right on a classic ATmega328 Uno,
where pins 0/1 *are* the USB UART, but wrong on an R4, where `Serial` is native
USB CDC and D0/D1 are `Serial1`. It would collide with your Python connection,
and it also pulls in the AVR `libstdc++` shim, which fails to compile.
