# 9.3 Hardware issues

## The arm returns `-1` for everything

```python
>>> mc.is_controller_connected()
-1
>>> mc.get_angles()
-1
```

`-1` means **no bytes came back**, not a malformed reply. Check in order:

### 1. Is the arm powered?

Its own supply, not USB from the R4. The M5 normally draws power from the
base, so an unpowered arm looks exactly like this.

### 2. Are TX and RX crossed?

```
R4 D1 (TX)  ---->  arm RX
R4 D0 (RX)  <----  arm TX
```

**TX to TX is the most common cause.** It is silent *and* harmful: two
push-pull outputs driving each other, one high, one low, with only the
drivers' internal resistance limiting the current. Power the arm down before
correcting it.

The diagnostic signature is silence at **every** baud rate:

```
1000000  -- no bytes --
500000   -- no bytes --
250000   -- no bytes --
115200   -- no bytes --
...
9600     -- no bytes --
```

If a sweep looks like that, stop investigating baud rates and protocol — the
link is electrically dead.

### 3. Is ground common?

R4 GND to arm GND. Without it UART does not work regardless of the data lines.

### 4. Are those actually the arm's UART pins?

The arm's UART reaches the base connector that the M5 seats into. If you wired
to a different header, or to pins that are only live when an M5 is present,
you get silence.

## Confirming the R4 itself is fine

This needs no arm and no arm power, because the R4 answers it itself:

```
send: fe fe 02 c1 fa
recv: fe fe 03 c1 18 fa
```

If that works, the board, firmware and USB path are all good, and the fault is
strictly on the arm side.

## Voltage levels

> The R4's D0/D1 are **5 V**; the M5Stack it replaces is **3.3 V**, and the
> MKR boards whose profile this configuration borrows are 3.3 V as well.

If the arm's UART is 3.3 V, the R4 to arm direction is outside spec. It does
function in practice, but use a level shifter — or at minimum a divider on the
R4 TX line — for anything left running unattended. The arm to R4 direction
needs nothing.

## Wrong version reported

`get_basic_version()` returning `1.3` instead of `2.4` means the sketch was
built against `MyPalletizerBasic.h` rather than `MyCobotBasic.h`.
`SYSTEM_VERSION` is 13 for a palletizer and 24 for a 280.
