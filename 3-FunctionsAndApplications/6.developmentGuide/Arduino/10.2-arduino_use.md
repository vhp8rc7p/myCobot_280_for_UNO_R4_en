# 6.1.2 Simple Use

Getting the stock `MyCobotBasic` library to build and run on an UNO R4.

## Install the library

```bash
git clone https://github.com/elephantrobotics/MyCobotBasic.git
```

Copy the cloned folder into your Arduino libraries directory:

| OS | Path |
|---|---|
| Windows | `Documents\Arduino\libraries\MyCobotBasic` |
| macOS | `~/Documents/Arduino/libraries/MyCobotBasic` |
| Linux | `~/Arduino/libraries/MyCobotBasic` |

Keep the folder named exactly `MyCobotBasic`. The repository ships no
`library.properties`, so it is a legacy-format Arduino library; the folder
name is what makes `#include <MyCobotBasic.h>` resolve. Restart the IDE after
copying.

## Configure it for the R4

Out of the box the library targets the M5Stack. Building for an R4 without
changing this fails:

```
M5Stack.h:178:2: error: #error "This library only supports boards with ESP32 processor."
MyCobotSaver.h:7:10: fatal error: FS.h: No such file or directory
```

The library's convention is to **replace the root `ParameterList.h` with the
one from your model's example folder**. For the UNO R4:

```bash
cp examples/MyCobot280/MyCobot280_Arduino/Mkr/ParameterList.h  ParameterList.h
```

Or edit the root `ParameterList.h` by hand — lines 10 and 13:

```diff
-#define MyCobot_M5 "m5"
+//#define MyCobot_M5 "m5"

-//#define MyCobot_Mkr "mkr"
+#define MyCobot_Mkr "mkr"
```

> ### Do not edit the copy inside the example folder
>
> `examples/MyCobot280/MyCobot280_Arduino/Mkr/ParameterList.h` is already
> configured correctly, which makes it look like the file to edit. **It is
> not used by the build.** Only the copy in the library root is compiled —
> the example folder's copy is a template to be copied *from*.
>
> Editing it and rebuilding produces the identical M5Stack error, with the
> compiler trace pointing at the root file:
>
> ```
> In file included from .../MyCobotBasic/ParameterList.h:28,
>                  from .../MyCobotBasic/MyCobotSaver.h:5,
>                  from .../MyCobotBasic/MyCobotBasic.h:7,
>                  from .../Mkr/AnglesControl/AnglesControl.ino:1:
> M5Stack.h:178:2: error: #error "This library only supports boards with ESP32 processor."
> ```

## Why the "Mkr" profile

The define is a **serial-port profile, not a board identity**. You do not need
to own a MKR. It does exactly two things:

```c
#if defined MyCobot_Mega || defined MyCobot_Mkr
#define mycobot_serial Serial1          // what the R4 needs
#endif

#if defined MyCobot_Mega || defined MyCobot_Uno
#include <hashtable-aux.h>              // AVR shim the R4 must NOT get
#endif
```

`MyCobot_Mkr` selects `Serial1` and avoids the AVR `libstdc++` shim in
`lib/avr-libstdcpp`. Both are correct for the R4, whose ARM toolchain has a
real standard library.

Do **not** use `MyCobot_Uno`. Besides mapping the arm to the USB port (see
[5.3 Hardware Interface](../../5.BasicFunction/5.3-HardwareInterface/RoboticArmElectricalInterface.md)),
it pulls in the AVR shim and fails:

```
avr-libstdcpp/new:40:10: fatal error: stddef: No such file or directory
```

## Select the board

**Tools → Board → Arduino UNO R4 Boards → Arduino UNO R4 WiFi** (or Minima),
then select the port.

## Examples

Use the sketches in `examples/MyCobot280/MyCobot280_Arduino/Mkr/`:

| Sketch | Purpose | Status on R4 |
|---|---|---|
| `AnglesControl` | joint moves driven by the Arduino | compiles unmodified |
| `CoordsControl` | cartesian moves | compiles unmodified |
| `GripperControl` | gripper | compiles unmodified |
| `Transponder` | USB↔arm bridge for Python control | **needs a one-line fix** |

`AnglesControl` is the right first test: it moves the arm without any host
software, so it isolates the Arduino-to-arm link.

> ### `Transponder.ino` does not compile for the R4 as shipped
>
> ```
> Transponder.ino:131:11: error: reference to 'data' is ambiguous
> ```
>
> The sketch has `using namespace std;`, and the R4 core pulls in `<array>`
> and `<string>`, which declare `std::data`. The global `int data` on line 14
> then becomes ambiguous against `std::data`. This does not occur on a real
> MKR with its older core.
>
> Rename the variable — line 14 and its five uses (131-133, 146, 147, 152):
>
> ```diff
> -int count = -1, data = -1;
> +int count = -1, rx_byte = -1;
> ```
>
> Leave `client_data`, `temp_data`, `atom_data` and `v_data` alone; they are
> unrelated identifiers. After the rename it compiles clean.
>
> To skip this entirely, use the prebuilt
> [MyCobot280_R4_Transponder](https://github.com/vhp8rc7p/MyCobot280_R4_Transponder),
> which bundles its own configured sources.

## Upload

Select the port and upload. If it fails with `No device found` or
`Serial port busy`:

- close any Python session, REPL or Serial Monitor holding the port, then
- **retry** — the R4 often needs a moment to settle after the port is
  released. Two failures followed by success on an identical third attempt is
  normal and does not indicate a fault.
